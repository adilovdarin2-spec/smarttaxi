# MASTER PROMPT — SmartTaxi V2 Premium UI/UX + Product Logic

Ты — senior product designer, UX architect, mobile app designer, fintech/taxi UX expert и frontend architect.

Задача: создать идеальный дизайн и логику многофункционального такси-сервиса SmartTaxi.

## 1. Общий контекст

SmartTaxi — сервис такси для города/региона. Приложение должно выглядеть не как простой сайт, а как дорогой, удобный, понятный и доверительный сервис уровня Kaspi / Yandex Go / InDrive, но со своим стилем.

Нужно создать единую экосистему:

1. Приложение клиента.
2. Приложение водителя.
3. Веб-панель оператора.
4. Веб-панель администратора.
5. OpenStreetMap-карта.
6. Система заказов.
7. Платежи.
8. Бонусы и промокоды.
9. Поддержка/чат.
10. Уведомления.
11. История поездок.
12. Управление водителями и пользователями.

## 2. Главная дизайн-задача

Сделать интерфейс бело-золотым, премиальным, чистым, удобным и понятным.

Цветовой стиль:
- Основной фон: теплый белый / светло-бежевый.
- Основные карточки: белые.
- Главный акцент: золотой.
- Текст: почти черный.
- Вторичный текст: серый.
- Ошибки: красный.
- Успех: зеленый.
- Карта: светлая OpenStreetMap.
- Главная кнопка: золотая.
- Вторичные кнопки: белые с тонкой границей.
- Нельзя делать грязный, перегруженный, темный или кричащий интерфейс.

## 3. UX-принципы

1. На каждом экране должно быть одно главное действие.
2. Золотая кнопка используется только для главного CTA:
   - Войти
   - Зарегистрироваться
   - Найти водителя
   - Принять заказ
   - Завершить поездку
   - Оплатить
   - Отправить заявку
3. Вторичные действия — белые кнопки с тонкой границей.
4. Карта должна быть главным центром экрана пассажира и водителя.
5. Адреса должны быть понятны с первого взгляда.
6. Водитель и клиент должны видеть только нужную им информацию.
7. Нельзя смешивать роли клиента, водителя, оператора и админа.
8. Интерфейс должен работать быстро и логично.
9. Важные статусы должны быть понятны цветом, текстом и иконкой.
10. Никаких лишних экранов ради красоты — только полезные.

## 4. Роли

### Клиент
Клиент хочет быстро заказать машину, понять цену, увидеть водителя, оплатить и не думать.

Главный flow:
Вход → регистрация → адрес отправления → адрес назначения → тариф → способ оплаты → поиск водителя → водитель найден → поездка → оплата → оценка → история.

### Водитель
Водитель хочет получать заказы, видеть цену, маршрут, клиента, баланс и доход.

Главный flow:
Регистрация → проверка документов → выход на линию → получение заказа → принять/отклонить → забрать клиента → завершить поездку → получить оплату → история/баланс.

### Оператор
Оператор решает проблемы:
- жалобы клиентов;
- жалобы водителей;
- проблемы с оплатой;
- ручное назначение водителя;
- отмены;
- спорные поездки;
- поддержка через чат.

### Админ
Админ управляет бизнесом:
- пользователи;
- водители;
- поездки;
- финансы;
- комиссии;
- тарифы;
- промокоды;
- поддержка;
- города/районы;
- статистика;
- активность водителей;
- заблокированные пользователи.

## 9. Логика карты

Использовать OpenStreetMap / Leaflet.

Карта должна показывать:
- точку отправления;
- точку назначения;
- маршрут;
- машину водителя;
- ближайших водителей;
- статус движения;
- кнопку геолокации;
- кнопку изменения адреса;
- светлую тему карты;
- золотой маршрут.

## 10. Состояния поездки

Статусы:
1. draft — клиент выбирает адреса.
2. priced — цена рассчитана.
3. searching — поиск водителя.
4. assigned — водитель назначен.
5. driver_arriving — водитель едет к клиенту.
6. arrived — водитель приехал.
7. in_trip — поездка началась.
8. completed — поездка завершена.
9. cancelled_by_client — отменено клиентом.
10. cancelled_by_driver — отменено водителем.
11. cancelled_by_operator — отменено оператором.

## 15. Качество интерфейса

Интерфейс должен:
- выглядеть дорого;
- быть простым для любого человека;
- иметь крупные кнопки;
- иметь хороший контраст;
- быть удобным на телефоне;
- не перегружать пользователя;
- объяснять, что происходит;
- давать быстрые действия;
- быть логичным для клиента и водителя;
- быть серьезным для админа и оператора.

## 16. Что нельзя делать

Нельзя:
- делать как обычный лендинг;
- делать маленькие кнопки;
- делать слишком много цветов;
- перегружать карту;
- путать меню клиента и водителя;
- ставить админские функции в клиентское приложение;
- использовать хаотичные иконки;
- делать темный интерфейс как основной;
- скрывать цену;
- скрывать статус поездки;
- делать непонятную регистрацию водителя.

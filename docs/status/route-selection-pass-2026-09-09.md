# SmartTaxi — выбор маршрута и направление выезда, 9 сентября 2026

Продолжение `075f0cf`. Изменён общий API для web/Flutter и ссылки отслеживания.
Локальный Docker пересобран. Production вручную не развёртывался, аккаунты,
заказы, GPS телефона, схема/миграции, оплата и SMS в этом проходе не менялись.

## Что подтверждено и исправлено

Выбор минимального `duration`, затем минимального `distance` при одинаковом
времени **уже существовал**. Этот этап не выдаёт прежнюю сортировку за новую.

- При построении активного участка сервер терял `heading/speed/accuracy`
  из `driver_locations`. На реальном ответе OSRM для улицы Амангелды маршрут
  начинался с курса 3°, даже когда тестовый входной курс автомобиля был 183°.
  Теперь курс передаётся как ограничение выезда, только если GPS свежий
  (до 12 с, допустимое опережение серверных часов до 5 с), точность ≤25 м,
  скорость ≥3 м/с. Нулевой курс — корректный север; отсутствующее значение,
  остановка, плохая точность и старый GPS не превращаются в направление.
- Используются `bearings=<курс>,45;` и ограниченный `radiuses`: 60 м для
  движущейся машины, 250 м для адресной точки. Приёмный конец не ограничен
  направлением; `curb`/объезд отдельных типов дорог не навязываются.
  Параметры сверены с [официальным OSRM API](https://project-osrm.org/docs/v5.24.0/api/).
- Раньше даже геометрия из другой части города могла выиграть сортировку,
  если её `duration` был меньше. Новый регрессионный тест сначала упал
  (`1 !== 480`), затем прошёл с проверкой близости начала/конца линии к
  запрошенным точкам. Проверка действует и при чтении кеша.
- Кеш `fastest-v3` учитывает провайдера и курс: север, юг и пассажирский
  предварительный расчёт не получают чужую линию или чужую ошибку.
- Водитель, пассажир и share-link используют один `buildActiveLegRoute`.
  При NoSegment нет повторного запроса с отброшенным курсом, который мог бы
  снова направить движущуюся машину назад. Существующая явно помеченная
  приблизительная линия tracking остаётся без манёвров; цена по ней не считается.

Это **не доказательство сокращения времени каждой поездки**. Корректный путь
из фактического направления движения иногда длиннее пути, начинающегося назад.
Выбирается самый быстрый из допустимых вариантов, которые вернул провайдер.

## Реальная проверка на локальном API

Команда: `rtk proxy docker compose exec -T api node src/tools/smoke-route-selection.js`.
Сценарий допускает только development и localhost API. Не создаёт заказы,
не обновляет GPS или аккаунты. Сверяет геометрию/метрики API с реальным OSRM.

Результат 2026-09-09 10:28 UTC, провайдер `https://router.project-osrm.org`:

| Тестовые точки (lng, lat) | Расстояние | Время | Смещение на дорогу, начало / конец |
| --- | --- | --- | --- |
| Атакент: 68.509144,40.8443546 → 68.5105,40.8505 | 1556 м | 307 с | 29.8 / 22.4 м |
| Жетысай: 68.324677,40.777134 → 68.33,40.785 | 1656 м | 215 с | 40.4 / 4.5 м |
| Мырзакент: 68.549994,40.665495 → 68.56,40.675 | 2231 м | 383 с | 7.3 / 45.6 м |

Для каждого из этих трёх запросов провайдер вернул **один** вариант.
Выбор среди нескольких вариантов проверен отдельными регрессионными тестами;
live-проверка не доказывает наличие всех возможных путей в дорожном графе.

Одна дорожная точка 68.509497,40.844343 → 68.5105,40.8505:
курс 3° дал старт 3°, 1556 м / 307 с; курс 183° дал старт 183°, 2166 м / 381 с.
Это реальные маршруты, но **тестовые входные курсы**, не поездка на телефоне.

## Осталось проверить

Реальные дорожные испытания перестроений, развязок, параллельных полос,
остановок и потери GPS. Нужен конкретный пример пользовательского плохого
маршрута для адресной приёмки. Гарантия самой быстрой дороги с учётом пробок
невозможна без подключённого источника трафика. Полнота OSM, реальные въезды
и закрытые проезды не дорисовываются; официальный адресный реестр остаётся
внешним блокером. Это не объявление всего продукта готовым к публикации.

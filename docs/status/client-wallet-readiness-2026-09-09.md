# Пассажирский кошелёк — безопасная готовность web/Android, 9 сентября 2026

Закрыт подтверждённый дефект кошелька, не весь release acceptance. Работа только
в `dev` и локальном Docker. Карты/маршруты, состояния поездки, финансовые расчёты,
схема и миграции в этом проходе не менялись. Production/SMS/мерчант не использовались.

## Подтверждённая проблема

Старый web-экран собирал полный номер карты и утверждал, что хранит только маску.
Сервис на деле сохранял полный PAN в `client_cards.card_number`, без банковской
токенизации. Пассажирское пополнение создавало только PENDING-заявку: пути её
реального зачисления нет. Android дополнительно обещал автоматическую обработку
таких заявок после будущего подключения платежей. Это не готовая интеграция.

## Что изменено

- API: новые POST `/api/clients/me/wallet/cards` и `/topup-requests` возвращают
  `503 CLIENT_WALLET_NOT_READY` после проверки авторизации/роли, до проверки полей
  и работы с профилем/записью. Прямые service-вызовы тоже закрыты, без обращения
  к executor. Summary явно возвращает `capabilities: {cardBinding:false,topUp:false}`.
  Флаг оплаты заказа не включает несуществующую интеграцию кошелька.
- Web: отдельный lazy-экран в общей бело-синей палитре, настоящий баланс кешбэка,
  история старых заявок, сохранённые записи карт и понятные состояния ошибки.
  Никаких форм PAN/пополнения и утверждения о банковской привязке. Пункт меню —
  «Кешбэк и история». Неизвестные суммы/даты не заменяются нулём/текущей датой.
- Android: тот же набор действий и ограничений; светлая/тёмная темы, RU/KK/UZ/ZH.
  Удалены прежние формы привязки/пополнения. Ошибки параллельных GET наблюдаются
  сразу через `Future.wait`; ошибка чтения не показывает ложный нулевой баланс.
- Удаление собственной старой записи требует подтверждения и действительного
  `{removed:true}`. После успеха читаются фактические данные сервера. Потерянный
  ответ/5xx не вызывает повторной отправки; действие блокируется до успешного
  обновления. Web также отбрасывает поздние callbacks после закрытия/смены сессии.
- Сохранены исторические GET, владелец/роль, удаление и старый default endpoint.
  Новые интерфейсы не представляют default-запись как платёжный инструмент.

### Настоящий локальный API и сайт

`src/tools/client-wallet-readiness-smoke.js` допускает только обычный loopback
origin и `env=development` до login; редиректы запрещены. Guard tests не обращаются
к сети. Реальная проверка использовала отдельного существующего seed-пассажира,
не аккаунт водителя на телефоне. Пустые POST bodies отклонены 503 до валидации;
GET до/после подтвердили неизменность списков (0 карт, 0 заявок). Платёжные реквизиты
не отправлялись, реальные записи карт/пополнений не создавались и не удалялись.

На `127.0.0.1:5175` проверен кошелёк существующего локального водителя в штатном
режиме пассажира. 360 и 320 px: нет горизонтального переполнения, нет PAN-полей,
refresh 44 px. После QA возвращён режим водителя «Не на линии»; новых заказов нет.
Итоговый Docker-сайт перезагружен, ошибок в browser log нет. Временный Vite 5176
остановлен, временная вкладка закрыта, viewport override сброшен.

## Что остаётся

1. Ранее сохранённые PAN не мигрировались и не удалялись. Реальные значения из БД
   не читались. До запуска владелец должен определить обработку исторических
   карточных данных; этот gate останавливает новые записи, но не очищает историю.
2. Реальная привязка карты/зачисление пополнений требуют отдельной мерчант-интеграции
   с токенизацией и подтверждённым учётом. Нельзя просто переключить capability
   или обещать автоматическую оплату старых PENDING-заявок.
3. Установка текущего APK, физический QA, moving GPS/TTS/background/push, оставшиеся
   visual/parity состояния и production capacity ещё не закрыты этим проходом.
4. RKA/meta/checksum, SMS sender/мерчант, юридические решения, лицензии/договоры,
   store/signing ownership и iOS/Mac остаются внешними. Production deploy отдельно
   авторизуется и проверяется. [Полный acceptance](RELEASE-REMAINING-2026-09-05.md).

Следующий безопасный локальный проход: воспроизвести поздние результаты действий
пассажира (избранные адреса/отмена) при смене сессии и закрытии экрана; исправлять
только подтверждённые случаи. Этот кошелёк не доказывает изоляцию всех иных действий.

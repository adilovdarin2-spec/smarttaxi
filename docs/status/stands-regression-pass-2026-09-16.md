# Стоянки — регрессионный проход 2026-09-16

Проведён повторный release-level проход без production-аккаунтов, заказов,
бронирований и записей в Railway Postgres.

## Подтверждено

- API `npm --prefix apps/api test` прошёл полностью. Проверка стоянок покрывает
  геозону, роли, очередь, места, бронь, административные маршруты и Socket.IO
  wiring.
- Отдельная API-проверка `check:stands` прошла: стоянка не принимает водителя
  вне радиуса, очередь не смешивает аудитории, места не перепродаются.
- Web stand tests: 23/23. Проверены круг геозоны, честное число свободных мест,
  очистка маркеров, camera fitting, разделение пассажирского/водительского
  представлений, realtime и формы числительных.
- Flutter `analyze` — без замечаний; полный `flutter test` — 330/330. В том
  числе stand-модели и экраны пассажира/водителя на ширине 320 px, с крупным
  текстом и в светлой/тёмной теме.
- `docker compose config -q` прошёл.

## Не подменяемая физическая проверка

Без доступного локального Docker API и подключённого тестового Android нельзя
заново воспроизвести физический GPS-цикл двух тестовых учётных записей:
водитель входит в радиус, занимает место, пассажир бронирует, водитель
подтверждает и выезжает. Последний такой проход зафиксирован в
`stands-and-cancellation-review-2026-09-11.md`.

Это не повод использовать публичные аккаунты или создавать тестовые заказы на
Railway. При следующем доступном локальном Docker/телефоне этот сценарий нужно
повторить только с local dev SMS и локальными test accounts.

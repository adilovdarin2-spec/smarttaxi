# Привязка домена к Railway — инструкция для владельца

Это ручные шаги в панели Railway и у регистратора домена — я их не выполняю
сам (это не то, что можно откатить кодом, и требует доступа к DNS/панели
Railway, которого у меня нет). Railway — единственный прод сейчас (см.
docs/DEPLOYMENT_VPS.md — VPS-конфиг помечен как неиспользуемый).

## Что сейчас

Бэкенд живёт на Railway по автоматическому адресу вида
`https://smarttaxi-api-production.up.railway.app` (Railway сам выдаёт домен
`*.up.railway.app` при деплое, без дополнительных действий). Это уже
рабочий публичный HTTPS-адрес — домен `api.smarttaxi.kz` нужен только для
красивого/постоянного адреса, технически сервис работает и без него.

## Шаг 1 — добавить домен в Railway

1. Открыть сервис API в панели Railway → вкладка **Settings** → раздел
   **Networking** / **Domains**.
2. Нажать **Custom Domain**, ввести `api.smarttaxi.kz`.
3. Railway покажет CNAME-запись, которую нужно добавить — что-то вида:
   ```
   Тип:   CNAME
   Имя:   api
   Значение: <что-то>.up.railway.app  (Railway покажет точное значение —
             оно уникально для каждого сервиса, копировать нужно именно
             то, что показано в панели, не из этого файла)
   ```

## Шаг 2 — добавить эту запись у регистратора домена smarttaxi.kz

В панели управления DNS для домена `smarttaxi.kz` (там, где домен был
куплен/зарегистрирован) добавить:

```
Тип:    CNAME
Имя/Хост: api
Значение (Target): <значение из шага 1, из панели Railway>
TTL:    по умолчанию (обычно 3600 или "Auto")
```

Если регистратор не разрешает CNAME на корневом уровне для поддомена
`api` — это стандартный случай, `api.smarttaxi.kz` как раз является
поддоменом (не корневым `smarttaxi.kz`), поэтому CNAME для него должен
работать без проблем у любого регистратора.

## Шаг 3 — подождать DNS и проверить в Railway

- DNS-изменения обычно применяются от нескольких минут до пары часов.
- В панели Railway напротив добавленного домена появится статус
  (обычно "Verifying" → "Active"), как только Railway увидит правильную
  CNAME-запись. Railway сам выпускает SSL-сертификат (Let's Encrypt) для
  домена — дополнительно ничего настраивать не нужно.
- Проверить: `curl https://api.smarttaxi.kz/api/health` должен вернуть
  тот же ответ, что и `curl https://<текущий-домен>.up.railway.app/api/health`.

## Шаг 4 — обновить переменные окружения

После того как домен заработал, обновить (там, где сейчас используется
старый VPS-адрес — см. `.env.example`, помечено как "NOT USED IN PROD"):

```
API_ORIGIN=https://api.smarttaxi.kz
API_PUBLIC_URL=https://api.smarttaxi.kz
CORS_ORIGINS=...,https://api.smarttaxi.kz,...
```

— в переменных окружения самого Railway-сервиса (панель Railway →
Variables), а не только в `.env.example` (тот — только шаблон для
локальной разработки).

## Если нужен домен и для веб-панели (app.smarttaxi.kz)

Те же 4 шага, отдельно для сервиса веб-панели (`apps/web`), если/когда он
тоже будет задеплоен на Railway — CNAME на `app`, а не `api`.

## Что НЕ нужно делать

- Не нужно ничего настраивать в `infra/nginx/` или `docker-compose.yml` —
  это VPS-конфиг, Railway его не использует и не читает.
- Не нужно вручную выпускать SSL-сертификат — Railway делает это сам после
  верификации домена.

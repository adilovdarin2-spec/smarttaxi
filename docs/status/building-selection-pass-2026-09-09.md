Продолжение [предыдущего QA и комплекта для заказчика](customer-handoff-2026-09-09.md).
База изменений: `bb0739717468ed8039a4642f6d507f4f03275b09`, ветка `dev`.
Проверки проводились только с локальным development Docker API `127.0.0.1:4001`
и собранным web `127.0.0.1:5175`. Production, реальные SMS и платежи не затрагивались.

## Исправления

- Web и native Flutter передают контур здания под меткой в reverse-geocoder.
  Используется существующий Polygon из векторной карты, а не выдуманный прямоугольник.
  Учитываются вогнутые контуры и отверстия/дворы. Адрес принимается только тогда,
  когда его координата находится внутри выбранного контура.
- При реальной проверке обнаружено, что OpenFreeMap объединяет отдельные дома
  в один большой MultiPolygon. Из него теперь извлекается только содержащий
  метку дом, а не вся группа зданий. Это покрыто регрессиями JS и Dart.
- Выбранный дом подсвечивается синим заполнением и тонкой обводкой ниже подписей.
  При открытии выбора камера ближе к домам (не менее 17.5), наклон 32°.
  Web повторно открывает текущий адрес, а не произвольный центр посёлка.
- Поздняя загрузка векторных тайлов повторно проверяет контур под неподвижной
  меткой. Ключи запросов/кеша включают контур: прежний ответ по близости не
  подменяет более точный ответ по зданию.
- Без доступного контура действует ограниченный поиск ближайшего адреса до 60 м,
  а не прежние 400 м. На карточке указывается расстояние, если оно больше 10 м.
  Для выбранного контура допускается размер здания до 500 м от метки, но адрес
  всё равно обязан находиться внутри. Слишком большая/невалидная геометрия
  отклоняется с `INVALID_SELECTED_BUILDING`.
- Локальный каталог выбирает адрес по расстоянию в метрах с поправкой долготы
  на широту, отбрасывает углы SQL bounding box вне радиуса и непригодные строки.
  Адрес, тип объекта и координаты теперь всегда принадлежат одному найденному
  объекту. Координаты далёкого ответа MapTiler больше не заменяются координатами
  метки, из-за чего он раньше выглядел точным.
- При недоступности внешних геокодеров локальные адреса продолжают работать.
  Неудача первого провайдера не останавливает цепочку остальных. Вызовы reverse
  ограничены 1.5 с на провайдера. Голая улица, код дороги, название посёлка,
  некорректные координаты и `fallback: true` не становятся подтверждаемым адресом.
- Flutter инвалидирует старый ответ сразу при движении карты/изменении строки,
  ещё до debounce. Это закрывает окно, в котором старый адрес можно было
  подтвердить под новой меткой. Закрытие/повторное открытие выбора также
  инвалидирует ответ. Нажатие на карту двигает метку; адрес сохраняет только CTA.
- В raster-навигаторе водителя исправлено растягивание машины родительским
  контейнером 64 dp: изображение ограничено 32 dp и центрировано на координате.
  Поворот по курсу сохранён. Причина подтверждена предыдущим снимком телефона;
  новый размер проверен widget-тестом, но ещё не повторным запуском на телефоне.
  Native route line и движок полноэкранного навигатора вслепую не заменялись.

Основные файлы: `routing.service.js`, оба reverse API route, общий
`packages/shared/src/building-selection.js`, web `MapView.jsx`/`ClientApp.jsx`,
Flutter `passenger_shell.dart`, `building_selection.dart`, `address_request_gate.dart`,
`driver_shell.dart`/`map_vehicle_marker.dart`, API-клиенты и модели адресов.
Добавлены отдельные тесты координат, контуров, очередности запросов и размера машины.
Schema, migrations и допустимые исходные статусы поездки не менялись.

## Незакрытые условия выпуска

Нельзя заявлять, что осталось только подключить SMS и оплату:

1. Нужны разрешение USB-установки и визуальный прогон нового APK на телефоне,
   затем дорожные испытания навигации, TTS, перестроения, фонового GPS и уведомлений.
   Widget-тест и статическая карта не подтверждают работу в реальном движении.
2. Контуры и адреса зависят от полноты исходных геоданных. Объекты без адреса,
   контуры сложнее допустимого размера, границы векторных тайлов и неразмеченные
   дома не становятся достоверными от оформления UI. Нужен официальный реестр
   `rka,label,lat,lng` с отдельным checksummed `meta.json` каждого региона.
   Павлодарский XLSX без координат не импортирован.
3. Локальный OSRM использует внешний `router.project-osrm.org`. Нужны production
   routing/map deployment и нагрузочный QA на выбранной инфраструктуре.
   Данных реального трафика здесь нет; «самый быстрый с учётом пробок» не обещается.
4. Полноэкранный водительский навигатор остаётся raster FlutterMap; остальные
   карты используют vector/native. Полная визуальная parity и приёмка каждого
   экрана/языка заказчиком ещё не подтверждены. Firebase Admin в local API не
   настроен: socket/in-app и тесты не доказывают доставку background push.
5. Сохраняются внешние блокеры предыдущего handoff: ИП/юридические решения,
   мерчант/официальный контракт оплаты, SMS sender ID, лицензии, iOS/Mac/stores,
   production DNS/TLS/секреты/мониторинг/backup и окончательная приёмка окружения.

Приложение не публиковалось, чужие изменения не откатывались, volumes не удалялись.
